# Recordings enabled by default — Design

**Date:** 2026-11-17
**Status:** Approved

## Intent and why

Crowd audio recording exists end-to-end (`RecordingInput` → upload → host approval → scheduler
plays in mix) but is invisible by default: `Room.recordingsEnabled` defaults to `false`, so new
rooms show no trace of the feature on the vote page, and the original author mistook the feature
for removed. The `false` default was accidental, not a consent gate. Recordings should be enabled
by default so the feature is present out of the box.

## Goals

- New rooms have `recordingsEnabled = true` at creation.
- Existing rooms (dev, test, prod) are flipped to `true` by migration — the `false` value was
  accidental, so nobody deliberately chose it; a host who wants it off can re-disable anytime.
- When a host disables recordings, voters see "Recorded sounds are paused by the host." —
  mirrors the existing text-directions paused message, so a disabled feature reads as paused,
  not removed.

## Non-goals

- `momentsEnabled` (stays `@default(false)`) — separate decision, not requested.
- `sampleApproval` (stays `@default(true)`) — host still approves each recording before it plays.
- No changes to the upload, approval, scheduling, or playback pipeline.

## Constraints

- SQLite cannot `ALTER COLUMN SET DEFAULT`; the default change requires Prisma's table rebuild.
- All DB-backed test files migrate their own SQLite files at module load, and E2E resets
  `test.db` via `scripts/e2e-reset-db.sh` — the migration propagates everywhere automatically.
- Bun everywhere; `bun run verify` gates completion.

## Approaches

- **Schema default flip + migration (chosen).** `prisma/schema.prisma` default → `true`, Prisma
  migration rebuilds the `Room` table, hand-edited to append `UPDATE "Room" SET
  "recordingsEnabled" = 1` so existing rows flip too. Single source of truth; raw SQL inserts
  also see the right default.
- **Explicit `recordingsEnabled: true` in `createRoom` only (rejected).** Schema and code
  defaults diverge; direct/prisma-raw inserts keep the wrong default; existing rooms stay
  hidden.

## Left to the builder

Exact migration SQL is generated by `prisma migrate dev --create-only` (rebuild), then reviewed
and edited to append the row update. Paused-message copy pinned in the plan.
